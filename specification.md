# Initial specification

The semantic transition is:

```text
(AuthorityState, CommandV1, ExplicitTime, CredentialFacts) ->
    (AuthorityState, Result<OutcomeV1, RefusalV1>)
```

Credential facts are trusted-boundary inputs, not claims that Aegis authenticated a
peer. Issuance and delegation publish opaque non-forgeable grant values only after
all scope, ancestry, capacity, time, and epoch checks pass.

Validation is total over admitted values. It checks engine instance, subject,
session binding when present, action, resource, epoch, expiry, revocation, and
delegation ancestry. A grant ID alone is never sufficient evidence.

The initial resource vocabulary will cover Agora participant/room actions, Chronos
task/worker actions, Vellum document actions, Moira workflow actions, Hermes stream
actions, and Daimon execution actions without importing those engines' state.

## Implemented volatile profile

`ActionSetV1` is a finite bounded lattice ordered by subset, with intersection as
meet, union as join, empty as bottom, and the closed action vocabulary as top.
Grant attenuation requires every child scope to be below a matching parent scope,
cannot extend expiry, and has bounded depth. Validation checks engine instance,
epoch, expiry, subject, optional session, resource, namespace, and action before
issuing redacted decision evidence. Epoch advancement invalidates all earlier
grants without rewriting historical decisions.

`Engine::issue` is intentionally a privileged adapter operation: this core does
not establish the caller's credentials. Grants have private construction and are
not cloneable, while a public identifier alone is never accepted by validation.
The selected local Unix adapter maps kernel-reported effective UID/GID pairs to
bounded principal/session facts; remote credential adapters and portable grants remain open. V1 deliberately selects
global epoch revocation and no durable ancestry or per-grant revocation facts; the
principal/session continuity rules are in `docs/authority-lifecycle.md`.

## Implemented durable local profile

The pure canonical checkpoint is exactly 48 bytes: `AEGISCP\x01`, the 16-byte
engine namespace, then big-endian u64 epoch, next-grant and next-decision
frontiers. Limits remain trusted host inputs. No grant, scope, principal,
session, credential or decision body is encoded. Unknown versions, nonexact
length, wrong expected namespace, disabled limits and epoch exhaustion refuse.
Recovery advances the epoch and preserves both frontiers; this pure operation
does not itself establish durability. No unfenced decoder or grant codec exists.

The trusted host stores `AEGISST\x01`, a big-endian u64 storage revision and that
checkpoint (64 bytes total). It requires matching strong load/receipt evidence
and revision correspondence. Creation commits the empty state. Reopen validates,
advances the epoch and commits the recovery fence before exposing the host.
Issue, attenuation, validation and revocation prepare privately, persist, then
publish. Domain refusal is an identity with no write. An offered store failure,
refusal, weak/wrong receipt or indeterminate result fences every authority use;
unreleased outcomes are dropped. Recovery can advance multiple epochs after lost
receipts, which is safe and never treated as grant restoration.

The explicit native profiles are the volatile core, generic persistence-gated
host, exclusive storage adapter, and bounded private Unix service. The service
keeps grants server-resident behind connection-session handles; it has no bearer-
grant wire protocol, network listener or UI. The separate `aegis-unix-peer`
adapter supplies the selected local credential provider without entering the core.
Issue, attenuation, and epoch revocation carry an exact expected authority epoch
and stale requests refuse before mutation or handle allocation. The namespace is reserved by the
host, not generated by the core or authenticated by an ID. Valid closed-store
rollback requires an external witness or namespace retirement; it is not solved
by a local epoch counter. New/versioned state only; no implicit migration.

## Public continuity conformance

The test-only `aegis-conformance` package depends solely on the public protocol.
Its harness binds three profiles to distinct verified principal/session facts and
controls reopening of the same durable authority without implicitly creating a
replacement session. The V1 suite proves that a non-administrator cannot issue,
a different authenticated session cannot use a grant handle, attenuation cannot
add actions or extend expiry, and an exact narrower scope cannot authorize a
different resource. It then proves global revocation clears live handles while
retaining a content-safe historical decision summary, and durable recovery
advances the epoch again while discarding all volatile sessions, grants and
decision summaries.

The harness does not authenticate credentials or define peer resource mappings.
A decision summary has no resource, subject, session or grant material and no
protocol command accepts it as authorization input. Passing the suite therefore
qualifies the bounded public service lifecycle, not a portable capability,
external rollback detection, or a peer adapter's mapping.

## Qualified peer resource mappings

Moira's adapter maps its stable exact-saga resource to `Moira/Administer` and
retains only decision attribution. Daimon's adapter binds an authenticated
Daimon principal and opaque authority context to one session-owned Aegis grant,
then requests `Daimon/Execute` for the selected profile and every distinct tool.
Profile and tool identifiers share the Daimon resource namespace and must not
alias semantically different deployment resources. Both adapters use only
Aegis's public client/protocol contract; grant handles remain inside their trusted
composition and every operation is revalidated against the current epoch.

## Optional external rollback witness profile

`aegis-witness` decorates the mechanism-level checkpoint store without importing
the authority engine, service, transport or local adapter. Before creation or
recovery it asks an independently provisioned witness to confirm true absence or
the exact loaded revision and bytes. Older or missing local state is rollback;
different bytes at the same revision are conflict; state ahead of the witness is
indeterminate. None is adopted automatically.

For a mutation, local durable commit precedes witness advancement, and witness
confirmation precedes host publication. Any non-confirmation or witness error
after local commit fences the live host because the durable winner is unknown.
The contract supplies no witness transport, credential, cryptography, quorum or
durability implementation; those claims belong to the concrete deployment.
