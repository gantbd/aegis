# Managed administration session

`aegis-admin-session` is Aegis's bounded application protocol for reusable
issue, attenuation and authorization on one authenticated public-client
connection. It contains no terminal UI, credential acquisition, socket
selection or daemon lifecycle. A standalone shell and Workbench supply those
edges and call the same `run` function.

The input is newline-delimited JSON. Every object has `"version":1` and one of
the closed commands `issue`, `attenuate`, `authorize`, `list`, or `close`.
Unknown fields, commands, versions, engines, actions, mixed-case identifiers,
duplicate actions and malformed 128-bit operation/resource names are refused.
The default owner accepts at most 16 commands, 16 KiB per line, eight retained
grants and 16 scopes per grant. An oversized line is drained through its newline
before another request is considered.

Issue and attenuation carry caller-chosen operation names, the exact current
epoch, explicit time/expiry and scopes, plus the exact confirmation generated by
`aegis-admin-command`. Attenuation names its retained parent. Authorization names
a retained operation and exact resource/action. `list` returns only redacted
operation, ancestry, epoch, expiry, scope-count and depth facts. Neither grant
nor decision handles appear in the application protocol.

Every input produces one JSON response. Syntax, version, bound, confirmation,
missing-name, duplicate-name, stale-epoch and service refusals are non-terminal.
Transport uncertainty or an impossible service reply emits one terminal response
and stops reading immediately. `close` and the command ceiling are also explicit
terminal responses. Transport error text is never emitted.

The protocol deliberately provides no retry, resume, credential field, durable
grant serialization or lost-reply reconciliation. Dropping the owner closes the
connection and destroys its session-local grants. Recovery means reconnecting
and deliberately rebuilding the desired authority under new operation names.
